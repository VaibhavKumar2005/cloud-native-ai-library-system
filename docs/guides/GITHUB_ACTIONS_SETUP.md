## Step 1: Repository Settings

### 1.1 Enable GitHub Actions
```
GitHub → Your Repo → Settings → Actions → General
✓ Enable local and third party Actions
✓ Allow all actions and reusable workflows
```

### 1.2 Enable workflow permissions
```
Settings → Actions → General → Workflow permissions
✓ Read and write permissions
✓ Allow GitHub Actions to create and approve pull requests
```

## Step 2: Configure Secrets

**Go to:** Settings → Secrets and variables → Actions → New repository secret

### Add these Secrets (Private API Keys)

```
1. AZURE_CLIENT_ID
   Value: (from Azure AD app registration)
   Example: ce3d23c1-c364-41e5-998c-e1d3cf4691b1

2. AZURE_TENANT_ID
   Value: (from Azure AD tenant)
   Example: a1b2c3d4-e5f6-7890-abcd-ef1234567890

3. AZURE_SUBSCRIPTION_ID
   Value: (from Azure subscription)
   Example: b7d6d48a-9b60-420c-b046-1e1512b81243

4. AZURE_OPENAI_KEY
   Value: (from Azure OpenAI API)
   Example: your-azure-openai-api-key-here

5. GROQ_API_KEY
   Value: (from Groq API)
   Example: gsk_your-groq-key-here

6. DOCKER_USERNAME
   Value: (Docker Hub username)
   Example: vaibhavkumar0412

7. DOCKER_PASSWORD
   Value: (Docker Hub access token)
   Example: dckr_pat_xxxxxxxxxxxx

8. GITHUB_TOKEN
   Value: (GitHub Personal Access Token)
   Auto-generated by GitHub, used for pushing to GHCR
```

### How to Get Each Secret

**Azure Secrets:**
```bash
# AZURE_CLIENT_ID, AZURE_TENANT_ID, AZURE_SUBSCRIPTION_ID
az account show --query "id" -o tsv  # Subscription ID

# From Azure AD App Registration:
az ad app list --display-name "GitHub" --query "[0].appId" -o tsv  # Client ID

az account show --query "tenantId" -o tsv  # Tenant ID
```

**API Keys:**
```bash
# AZURE_OPENAI_KEY
# From: Azure Portal → OpenAI resource → Keys and Endpoint

# GROQ_API_KEY
# From: https://console.groq.com/keys
```

**Docker Hub:**
```bash
# DOCKER_USERNAME: Your Docker Hub username

# DOCKER_PASSWORD: Create Personal Access Token
# Docker Hub → Account Settings → Security → New Access Token
# Scopes: Read, Write, Delete
```

## Step 4: Verify Workflow File

Check that `.github/workflows/ci-cd.yml` exists and has these sections:

### Section 1: Trigger Events
```yaml
on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]
  workflow_dispatch:
```

### Section 2: Environment Configuration
```yaml
env:
  REGISTRY: docker.io
  BACKEND_IMAGE: vaibhavkumar0412/verirag-backend
  FRONTEND_IMAGE: vaibhavkumar0412/verirag-frontend
  AZURE_OPENAI_ENDPOINT: ${{ secrets.AZURE_OPENAI_ENDPOINT }}
```

### Section 3: Jobs (5 stages)
```yaml
jobs:
  validate-environment:
    # Stage 1: Check secrets and setup
  
  test-and-validate:
    # Stage 2: Run tests
  
  security-scan:
    # Stage 3: Trivy scan
  
  build-push-acr:
    # Stage 4: Build and push Docker images
  
  deploy-aca:
    # Stage 5: Deploy to Azure Container Apps
```

## Step 5: Understand the Workflow

### Stage 1: Validate Environment
```yaml
# Checks that all required secrets are present
# Generates metadata (short SHA, image tags)
# Takes: ~30 seconds
```

### Stage 2: Test & Validate
```yaml
# Runs: Test suite (39 pytest tests)
# Runs: Frontend build verification
# Generates: Code coverage report
# Takes: ~2-3 minutes
```

### Stage 3: Security Scan
```yaml
# Scans: Docker images for vulnerabilities (Trivy)
# Reports: HIGH and CRITICAL severity issues
# Fails job if critical vulns found
# Takes: ~1 minute
```

### Stage 4: Build & Push to ACR
```yaml
# Builds: Backend Dockerfile
# Builds: Frontend Dockerfile
# Pushes: Images to Azure Container Registry
# Tags: With commit SHA and 'latest'
# Takes: ~2-3 minutes
```

### Stage 5: Deploy to ACA
```yaml
# Updates: Container app image
# Sets: Environment variables
# Runs: Health checks
# Takes: ~2 minutes
```

## Step 7: Review Workflow Results

### Success Indicators ✅
```
- All 5 stages show green checkmarks
- No RED labels
- Final message: "✅ Workflow passed"
- Deployment shows "in progress" then "succeeded"
```

### Common Failures ❌

**Test Stage Fails:**
```
Error: ModuleNotFoundError: No module named 'ai_engine'
→ Fix: Ensure requirements.txt is in apps/backend/

Error: E RuntimeError: Vault connection failed
→ Fix: Mock provided in conftest.py should cover this
```

**Build Stage Fails:**
```
Error: docker build from repository failed
→ Fix: Check Dockerfile has no syntax errors
→ Run locally: docker build -f apps/backend/Dockerfile apps/backend

Error: Image push failed
→ Fix: Check Docker Hub credentials (DOCKER_USERNAME, DOCKER_PASSWORD)
```

**Deploy Stage Fails:**
```
Error: Container App does not exist
→ Fix: Ensure azure-deployment-setup.ps1 was run first

Error: Health check failed
→ Fix: Check API endpoint is responding
→ Run: curl https://your-api/api/health/

Error: Image pull failed
→ Fix: Ensure ACR credentials are configured
→ Check: Image exists in ACR: az acr repository show
```

## Step 8: Configure Azure OIDC (For Production)

If deploying to Azure, use OIDC for secure authentication instead of secrets:

### 8.1 Create Azure AD Application
```bash
# Create app registration for GitHub
az ad app create --display-name "GitHub-VeriRAG"

# Get the app ID
APP_ID=$(az ad app list --display-name "GitHub-VeriRAG" --query "[0].appId" -o tsv)

# Create service principal
az ad sp create --id $APP_ID

SP_OBJECT_ID=$(az ad sp show --id $APP_ID --query "id" -o tsv)

# Assign the "Contributor" role to the subscription
az role assignment create --role "Contributor" --assignee-object-id $SP_OBJECT_ID
```

### 8.2 Configure the OIDC Trust
```bash
# Add federatedIdentityCredentials to the app
az ad app federated-credential create \  --id $APP_ID \
  --parameters @federation.json
```

**federation.json:**
```json
{
  "name": "github-verirag",
  "issuer": "https://token.actions.githubusercontent.com",
  "subject": "repo:VaibhavKumar2005/cloud-native-ai-library-system:ref:refs/heads/main",
  "audiences": [
    "api://AzureADTokenExchange"
  ]
}
```

### 8.3 Update Workflow to Use OIDC
```yaml
- name: Azure Login
  uses: azure/login@v1
  with:
    client-id: ${{ secrets.AZURE_CLIENT_ID }}
    tenant-id: ${{ secrets.AZURE_TENANT_ID }}
    subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
```

**Pros:** 
- No long-lived secrets
- Automatic token rotation
- Audit trail of who deployed when

## Step 10: Troubleshooting Workflow Issues

### "Secret not found" error
```
✓ Check Settings → Secrets
✓ Verify secret name matches exactly (case-sensitive)
✓ Ensure secret has a value (not empty)
✓ Re-save the secret
```

### "Permission denied" errors
```
✓ Check: Settings → Actions → General
✓ Set to: "Read and write permissions"
✓ Enable: "Allow GitHub Actions to create pull requests"
```

### "Docker build fails"
```
# Test locally first:
cd apps/backend
docker build -t test:latest .

# If local build fails, fix it before pushing
# Workflow won't magically fix local issues
```

### "Azure authentication fails"
```
# Verify Azure secrets:
az account show --query "id"  # Should match subscription
az ad sp show --id $CLIENT_ID  # Should exist

# If using OIDC, test federation:
az ad app federated-credential list --id $APP_ID
```

## Security Best Practices

### 1. Rotate Secrets Regularly
```
Every 90 days:
- Azure OpenAI key
- Groq API key
- Docker Hub token
- GitHub PAT

Update in: Settings → Secrets
```

### 2. Minimize Secret Permissions
```
Docker Hub Token:
- Scopes: Read, Write, Delete (minimal required)
- NOT: Full account access

Azure Service Principal:
- Role: Contributor (only needed for this project)
- Scope: Subscription level (not higher)
```

### 3. Audit Workflow Runs
```bash
# See who triggered deployment
GitHub → Actions → Workflow run

# See what code deployed
GitHub → Actions → Workflow run → "Deployed commit"

# View deployment logs
az deployment group show --name VeriRAG-deployment --query "properties"
```

### 4. Never Commit Secrets
```bash
# Good:
AZURE_OPENAI_KEY=${{ secrets.AZURE_OPENAI_KEY }}

# Bad:
AZURE_OPENAI_KEY=sk_actual_key_here!!!  ← NEVER DO THIS

# If you accidentally commit a secret:
git filter-branch --force --index-filter "git rm --cached --ignore-unmatch .env" HEAD
git push origin --force-with-lease main
# Then IMMEDIATELY rotate the leaked key
```

### 5. Use Branch Protection
```
Settings → Branches → Add rule for 'main'
✓ Require status checks to pass
✓ Require code reviews before merging
✓ Dismiss stale approvals
✓ Require branches to be up to date
```
